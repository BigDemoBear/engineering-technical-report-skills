# 科技文稿标点与序号检查 Skill

检查中文科技论文、科学技术报告及其章节中的标点、标题层级和分项序号。可独立使用，也可由科学技术报告写作技能在初稿形成后和最终交付前调用。当前版本：**1.1.1**。

本页供使用者阅读；AI 执行入口为 [SKILL.md](SKILL.md)。

## 检查什么

| 类别 | 主要内容 |
| --- | --- |
| 标题与分项 | 标题角色、层级与编号，正文分项顺序，括号序号后多余点号，序次语的标点 |
| 连接号与范围 | 时间、地域、数值范围和文献页码中的连接符，区分数学减号及负号 |
| 冒号 | 提示语、转述、分项引导和公式引导处是否需要冒号 |
| 分号与句号 | 句内层次、并列分项及分项结束的断句是否一致且符合语义 |
| 引号与书名号 | 并列时顿号的使用，以及版本括注、标准编号等插入成分的例外 |

不重写技术论证，不改技术数值，不批量替换数学符号。目标单位模板和本次明确要求优先于通用惯例；公式、代码、英文文献和公文编号不能直接套用中文正文规则。

## 如何使用

将完整 `scientific-punctuation-check` 目录放入个人技能目录。使用当前宿主识别的技能目录，例如 Windows 的 `%USERPROFILE%\.agents\skills\`；与主写作技能配套时，两者并列放置。重新打开会话后确认技能可见，也可在请求中直接指定本目录的 SKILL.md 路径。

**只审阅，不修改：**

> 使用 $scientific-punctuation-check，检查这份原稿的标点、标题与分项编号。按位置、原文、建议和理由列出问题，不修改文件。

**修正并另存：**

> 使用 $scientific-punctuation-check，修正这份报告中确定的标点和序号问题，另存副本。存在多种解释的地方保留并说明，不改技术数值和数学含义。

**遵从指定模板：**

> 按附件中的编号要求检查报告，不套用默认三级标题形式；同时检查分项、冒号、分号和并列书名号。

与主技能联用时通常无需单独下指令，主技能会在适用阶段读取规则并执行审校。

## 工具与判断如何分工

1. **脚本定位。** `check_punctuation.py` 扫描字符候选，并通过 `inspect_numbering.py` 提供标题样式、手工前缀、自动编号定义等结构证据。
2. **AI 审校。** 结合完整句、分项组、标题树及模板，逐项判为确定问题、疑点或允许的变体；脚本没有命中的语义问题也需检查。
3. **修改与显示复核。** 已获授权时修正确定问题，复读受影响内容；Word 自动编号的实际显示及排版变化需查看渲染页面。

候选需结合上下文判定。例如 `（1）` 可能是正文分项或式号，应先确定其角色。

## 手动扫描

两个脚本使用 Python 3 标准库，不需要额外 Python 包。在本技能目录执行：

```text
python scripts/check_punctuation.py "报告.docx"
python scripts/check_punctuation.py "报告.docx" --heading-mode template
```

默认 `decimal` 模式检查 `1 / 1.1 / 1.1.1` 的级数和部分父子关系；使用其他编号规范时选 `template`，先列结构证据，再按模板审查。

- 输入支持 UTF-8 TXT、Markdown 和 DOCX；脚本只读，结果以 JSON 输出，不修改原稿。
- 退出码 **0** 表示扫描完成，可能仍有候选；**2** 表示输入或读取失败。它与主技能部分检查脚本的退出码含义不同。
- DOCX 扫描覆盖正文与表格段落。PDF、扫描件和图片需借助宿主阅读/OCR，并对照原页。
- 自动编号的计数与重启、复杂字段、截图、页眉页脚、脚注尾注及句法层次需要另查。字符扫描还会跳过已识别的代码、数学区域、URL、路径、参考文献区和删除修订。
- 确定问题按上下文逐项修订，保留数学符号和合法标点。

## 结果如何交付

短文可直接返回问题表：`位置 | 原文 | 建议 | 判定 | 规则编号与理由`。长报告分别保存原稿发现、实际修改和成稿复核，并区分字符候选、结构候选与语义判定。

没有发现确定问题时，也应说明实际检查范围、适用规则和未覆盖内容；未核实疑点不得记为已修正。仅审阅时不改文件，修订已有文稿默认另存副本。检查记录不自动插入正式报告正文。

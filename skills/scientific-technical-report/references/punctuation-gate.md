# 独立标点与序号审校触发

关联技能：`scientific-punctuation-check`，入口为同级技能目录中的 [SKILL.md](../../scientific-punctuation-check/SKILL.md)。优先按当前宿主技能列表给出的真实路径读取。

## 触发时机

- 整篇或多章节中文科技报告初稿形成后，执行一次完整的适用规则审校。
- 最终交付前核对当前版本；初查后标点、编号、相关句段或 Word 列表发生变化时复查受影响部分，否则复用已确认记录。
- 只修改一段或一节时，检查修改范围、相邻句和所属分项组。用户明确不做审校、只保留原文或只要提纲时遵守本次范围。

主写作任务已授权撰写/修订时，确定的标点问题随正文修正，无需逐项申请确认。只查请求只给结果。语义或模板不明的疑点保留说明，不强行改动。

## 实际执行

1. 打开独立技能入口及其 rules.md，按其工作流运行。
2. 修改已有长报告时先保存原稿扫描与标题/分项清单，不能只扫描改后稿来描述原稿质量。候选扫描同时输出字符候选与结构候选；默认按数字标题层级检查，采用其他模板时用 `--heading-mode template` 并依据专用配置人工核对。自动编号读取样式/列表定义，但实际计数与显示仍看渲染。
3. 大模型逐项检查完整标题树及分项组，分清章节、正文列项、式号和文献号；随后核对连接号、冒号、句读及并列引号等适用类别。长报告独立记录“原稿发现 → 修改 → 成稿复核”，每项有位置、原文、判断、理由及结果。各类别记录检查范围及判定结果，区分脚本候选与语义审查。
4. 返回检查版本/范围、已修正问题、仍需核对的疑点和未覆盖部分；短段可直接给简短摘要。
5. 数值、单位、公式、引文、脚注及实际 Word 编号显示未被误改；布局变化后再做渲染检查。审校记录不自动加入正式报告正文。

若关联技能确实未安装或路径失效，先检查宿主技能列表及项目中的同名技能。仍不可用时报告缺少的技能路径；在可访问安装源且已获授权时恢复关联后继续检查。

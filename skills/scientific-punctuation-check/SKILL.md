# 科技文稿标点与序号检查

只审查标点、序号及相关结构，不重写技术论证、不变更数值和数学符号。覆盖标题与序号、连接号、冒号、句内层次及引号书名号五类内容；逐条规则与例外见 [rules.md](references/rules.md)，公开核对入口及适用边界见 [source-notes.md](references/source-notes.md)。

## 何时执行

- 用户明确要求检查中文科技文稿的标点、序号或连接号时，独立执行。
- `scientific-technical-report` 完成整篇初稿后、最终交付前执行；初查后没有相关改动时复用已确认结果，最后核对当前版本。局部改写只检查修改范围及相邻句，不重新审查全文。
- 原稿只要求审阅时给问题清单，不改文件；已授权撰写或修订时，可修正确定问题并复核。修改已有文稿默认另存副本。
- 用户明确限制为提纲、原文摘录、保留原标点或不做审校时遵从其范围；引用中的原文不擅自“纠正”。

## 先确定检查口径

读取稿件和当前模板，区分标题、正文分项、算法步骤、图表题注、数学表达、引文、参考文献和代码。学校/期刊/项目模板或用户本次明确要求优先；无规定时才使用本技能的科技文稿审校约定。三级标题是默认建议，不是对所有文档的硬上限。

核对可见编号：Word 标题与列表可能来自自动编号，不一定存在于纯文本。检查样式、列表定义或渲染后的编号，避免补入重复编号。不能把带 `1.1` 的章节编号、数字 `1.5`、式号 `(1)` 和分项标记 `(1)` 当成同一场景。

## 检查流程

1. **读取规则并定位候选。** 读取 rules.md 全部规则。修改既有长报告时先保存原稿结果及标题/分项清单；不能只扫改后稿来回答原稿是否有问题。可用只读脚本对 TXT、Markdown 或 DOCX 做候选扫描，命令见下；也可直接审阅短文。候选结果不是定论。
2. **逐项结合上下文判断。** 依规则编号审阅：N01—N04 标题/序号，C01—C03 连接号/范围/页码，A01—A03 冒号，S01—S02 句内层次和分项结束，Q01—Q02 并列书名号/引号及例外。脚本未命中也需检查适用的语义规则。
3. **分类。** 分为确定问题、需核对语义/模板的疑点、允许的变体或无需修改。不要把纯风格偏好计为错误。记录位置、原文、建议、规则及依据；跨段问题引用必要上下文。
4. **修订并复核。** 在授权范围内修正确定问题；关键语义有多解时保留并说明，不擅自选择可能改变技术含义的断句。修改后复读完整句/分项组，确保层级、指代和逻辑不变。Word 修改保留 run 格式、公式、脚注和字段，布局变化后渲染检查。
5. **返回结果。** 提供简洁检查摘要和问题表；无问题也说明已实际检查的类别、稿件范围与未覆盖项。大稿可保存独立审校记录；短段无需额外文件。给主写作流程返回已修正项、剩余疑点、检查版本与未检查部分。

## 候选扫描工具

```text
python scripts/check_punctuation.py <稿件.txt|稿件.md|稿件.docx>
python scripts/check_punctuation.py <稿件.docx> --heading-mode template
```

使用当前宿主 Python；脚本只依赖标准库，读取稿件，在标准输出返回 JSON，不修改输入。支持 UTF-8 TXT/Markdown，DOCX 读取正文和表格段落；PDF 应通过宿主 PDF 阅读/OCR 能力取得文本并核对原页，不能用本脚本直接证明 PDF 已检查。

脚本检查多余的序号点号、疑似序次语误用顿号、标题编号末尾点号、疑似范围连接符、公式引导语冒号、分项引导语冒号和简单的书名号/引号并列。另由 `inspect_numbering.py` 读取标题样式及继承的大纲级别、手工前缀、自动编号定义，输出完整标题/分项证据与结构候选。默认 `decimal` 核查 `1/1.1/1.1.1` 的级数和部分父子关系；其他规范用 `template` 模式只列证据，再按指定模板审查，不硬套默认。`[1]` 作三级标题是否合适由标题角色和配置决定，不能全局禁止方括号。

字符扫描跳过已识别的代码、数学定界区、URL、路径、参考文献区和删除修订；结构清单可能含数字开头的普通文字，必须按语义筛选。自动编号的计数、重启、样式链接和实际显示不由脚本模拟验收；复杂字段、截图、页眉页脚、脚注尾注及句法层次仍需单独检查。

退出码 0 表示扫描完成，包括有候选的情形；2 表示读取或输入失败。输出状态为 `candidates` 或 `no_candidates`。完成扫描后，按第二步结合上下文审阅适用规则，再逐项修订。

## 场景判定

- 中文标点规则作用于汉语文字；不把全角标点强加到英文引文、DOI、代码、路径和软件标识中。
- 数学减号、负号、区间、比值冒号、函数/集合记号和数字小数点按数学语义保留。公式前的中文引导标点与公式内部符号分别处理。
- `1 标题`、`1.1 标题` 末尾不加点；正文列项 `1. 内容` 可以用下脚点。中文 `一、内容` 与阿拉伯数字 `1、内容` 不混为一谈。`一是……`、`首先考虑……` 不机械补逗号。
- 直接相邻的书名号/引号之间通常去掉顿号；出现版本括注、标准编号或其他插入成分时重新判断，不能全局删除 `》、` 或 `”、`。
- 数值范围允许多种规范形式，优先保证语义清楚并遵从模板；参考文献页码按实际著录样式处理，不强制写成数学减号。

## 检查输出

建议问题表：`位置 | 原文 | 建议 | 判定 | 规则编号与理由`。引用用户提供的依据时注明可核对位置；引用标准时注明真实核对过的条款。未确认的疑点不记为已修正，未读的附件不记为已覆盖。

长稿分别保存字符扫描结果、结构清单和语义审查记录。报告原稿问题、改了什么和成稿剩余问题三个阶段；`lexical_candidate_count` 与 `structural_candidate_count` 不混为“错误数”。语义检查记录完整分项组、上下文及页面判断，与脚本候选结果分别保存。

本技能可独立运行，不依赖主写作技能；与主技能协作时仅返回本次审校结果，不把检查台账插进正式报告正文。

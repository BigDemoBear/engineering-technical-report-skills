# 按报告目的组织内容

按报告目的选取适用章节，用户给定的目录和项目模板优先。

| 类型 | 核心问题 | 可用章节起点 | 不应强加的内容 |
| --- | --- | --- | --- |
| 科研/技术研究报告 | 解决了什么技术问题，如何得到结果 | 目的与背景；研究对象和方法；算例/试验；结果与讨论；结论；参考文献；必要附录 | 普通报告不必宣称创新，不固定结论条数 |
| 实验或仿真分析报告 | 特定条件下发生什么、原因与效果如何 | 目标；原理与模型；设备/参数/工况；步骤和指标；结果比较；误差与限制；结论 | 无记录不补设备型号、软件版本或已执行步骤 |
| 技术调研/文献综述 | 现有方法如何分类、证据和适用条件怎样 | 范围与检索方法；技术分类；代表性证据；比较与不足；对本课题的判断；参考文献 | 不强制原始实验结果，也不自动声称系统综述或检索穷尽 |
| 技术方案/可行性分析 | 方案为何可行，怎么验证 | 需求与边界；候选方案与依据；技术路线；参数和计算；验证计划；约束和预期成果 | 未执行验证用将来时，预期指标不能写成已达成 |
| 专题技术总结 | 某方法、算法或现象的原理与使用方式 | 问题；定义与原理；方法与条件；已有算例；适用性与使用建议 | 没有算例时不生成假案例，不把教材复述包装成创新 |

正式长报告视要求增加封面、摘要、关键词、目录、符号表、图表清单及附录。没有报告编号、项目编号、作者、日期、密级或资助信息时不捏造；密级只能来自有权确定的真实要求，不能凭空赋予或一律禁止。

大纲中每个核心节检查：本节问题是什么；证据在哪；与上一节的关系是什么；读者最终应理解什么。简短段落修改不需要交付这些内部记录。

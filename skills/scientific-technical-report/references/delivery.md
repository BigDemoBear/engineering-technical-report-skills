# 文档生成与交付检查

## Word 输出

若宿主提供 documents/DOCX 技能，使用它处理文件生成、公式、字段和渲染；文件操作遵循其工具要求。也可按下列流程使用宿主可用的文档工具。

1. 按 [format-profiles.md](format-profiles.md) 先选默认配置、专用配置或用户指定样例，再另存新文件。无指定要求时用 `assets/technical-report-template.docx`；示例段落和旧槽位不进入正式成稿。生成过程不改模板原件。
2. 对授权的格式范围按选定配置处理页面、字体、行距、题注和编号，不混用原稿与默认值却不说明。默认不生成页眉、页码、封面、目录及图表清单；专用要求覆盖默认。标题已关联自动编号时不手工重复同一编号；题注与引用需更新并核对实际显示，不能只看文本提取。
3. 公式优先采用可编辑 OMML，已有 MathType 文档保留原体系。复杂公式保留可编辑数学源，逐式核对转换结果，记录尚需处理的公式。
4. 优先使用宿主提供的渲染器。需要 LibreOffice 时使用宿主捆绑版本，不擅自调用用户桌面安装；Windows 环境可使用可用的 Word PDF 导出。没有可用渲染器时不反复安装或修改系统，保留可编辑文件并明确“版式未验证”。
5. 渲染后查看全部页面及关键公式/图表：无缺字、截断、重叠、标题孤行、表格越界和异常空白。修复后重新检查受影响页面，最终页数变化时重新核对全页覆盖。

记录渲染工具和实际检查页码；字段更新、字体及渲染器差异可能影响分页。

## 局部修改与保真

- 默认另存副本。保留用户未要求更改的章节、脚注、图像、公式、批注、修订及引文字段。
- 精准修改 run 或 OOXML 节点，不把带复杂格式的一整段重建为纯文本。
- 检查结构变化是否符合预期，再检查实际渲染。嵌入图片和公式数量相同不能证明外观未受损。
- 删除或增补内容导致编号变化时更新引用；不能以隐藏错误、删检查项或统一改为纯文本的方式让验证“通过”。
- 对整体排版修订，原文已有的整段误加粗、错号和不一致段距仍须检查；保护技术强调、公式和未授权部分，不把全部直接格式无差别保留或清空。

## Markdown 或 LaTeX 输出

Markdown 重新读取已保存全文，检查标题层次、表格列数、公式定界、引用链接和异常字符，并用可用预览器检查实际显示。交付记录区分源文本检查和页面检查。LaTeX 源码按请求交付并注明编译状态；PDF 交付前完成编译和页面检查。

## 内容终检

- 对照选定格式配置检查各角色；运行适用的 `scripts/audit_format.py` 后处理候选，并查看全页渲染。表格边框/布局、题注位置、符号正斜体、复杂继承与未映射角色另作实际核对。
- 按 [punctuation-gate.md](punctuation-gate.md) 实际执行独立标点/序号审校，保留当前版本的检查范围与未解决项；不以台账脚本或文本抽取代替。
- 按 [manuscript-checks.md](manuscript-checks.md) 检查实际交付版本的占位与结构残留、适用的引用和显式定位关键数值；候选结合语义处理，转换后的 Word 重新检查。
- 技术目标与结论对应，方法、条件和指标足以理解结果。
- 关键数值回到来源；同一对象同一条件下的重复数值、单位和定义一致。
- 引用支持具体论断；只看元数据或未取得全文的来源不标为已读。
- 图、表、公式在正文有必要引用，编号和题注正确，数学/物理含义无歧义。
- 图表中的缺测、未测量、不适用与数值 0 明确区分，不用 0 代填；按要求保留图表出处。
- 没有虚构作者、项目号、软件版本、实验步骤、数据、参考文献或完成状态。
- 重要局限保留；普通内部工作记录单独保存。按用户和目标单位要求处理可复现性信息、资助、作者及 AI 披露，不能一律禁用相关词。
- 字数/页数有要求时记录统计工具及统计范围；除非规则明确，不将有利的部分计数宣称为全文合规。

## 输出形态

输出用户要求的成品文件；需要时保留 Markdown/LaTeX、图表源或计算记录。证据记录和缺项说明独立于正式报告，文件名清楚。交付说明只陈述实际做过的检查；缺关键数据或未完成版式检查时标为草稿。
